# Dashboard Integrity Audit: Metric Authenticity & Data Scoping

## Executive Summary
This audit inspects the authenticated member dashboard (`/dashboard`), its backend controller (`server/src/controllers/dashboardController.js`), and its React view (`src/pages/DashboardPage.jsx`).

The platform strictly prohibits fabricated member activity, deceptive percentages, or hardcoded mock counters. Every metric presented to a member must directly derive from their own scoped MongoDB documents and relationship models.

## 2. Recommendation Engine Authenticity

### 2.1 Absence of Fabricated Match Scores
- The system **does not** generate synthetic "AI 98% Compatibility" numbers.
- Recommendations are generated by `server/src/services/matchingEngine.js` using deterministic criteria:
  1. Gender compatibility (mandatory)
  2. Same-surname / gotra exogamy exclusion (community rule)
  3. Blocked user exclusion (bidirectional: `myBlocked` and `blockedBy`)
  4. Partner preference evaluation:
     - Age range (strict or soft penalty)
     - Height range
     - Marital status match
     - Education level
     - Native district proximity
     - Dietary preference compatibility
- Only candidates scoring >= 50% compatibility are considered for recommendations.
- If a candidate has no matching attributes, no fraudulent score is assigned.
- If a member has configured zero partner preferences, recommendations fallback to recently active, verified community profiles with transparent labeling ("Based on active community members").

## 3. Realtime Refresh & State Consistency

- The dashboard subscribes to `ksm:realtime` window events propagated by `RealtimeBridge.jsx` over Socket.IO.
- When another member sends an interest or accepts an interest:
  1. Socket.IO pushes an event to the recipient.
  2. `RealtimeBridge` emits `ksm:realtime`.
  3. `DashboardPage` automatically triggers an asynchronous background re-fetch of `/dashboard`.
  4. Metric counters update live without requiring a full browser reload.
